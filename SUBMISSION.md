2. In "Sharing", enter `bob@example.com` and click Share.
3. In a second browser profile (or after logging out), log in as Bob: the document is under "Shared with me", labelled "Shared by Alice".

## 5. Incomplete / deliberately deprioritised
- No live co-editing and no cursors: concurrent edits use last-save-wins with 409 detection. Presence is awareness only. Reason: out of scope for the time available (would need Yjs + Tiptap Collaboration).
- Editor role only: shared users can edit; there is no read-only viewer role.
- Seeded accounts only: no sign-up or password reset.
- Comments are document-level only (a thread under the editor), not anchored to a text selection; no replies tree, no notifications, no suggestion mode. No version history.
- `.docx` images and tables are dropped on import (also colours, fonts, unsafe HTML).
- Size limits: 2 MB upload, 512 KB converted import, 2 MB save body, 3 MB uncompressed `.docx`. Reason: the Fly VM has 256 MB; a crafted 4 MB save and a 4.9 MB-expanded `.docx` each killed it (see `ARCHITECTURE.md`). The `.docx` check reads sizes declared in the zip, so a forged header could still pass; `--max-old-space-size=128` mitigates parallel crafted saves but does not eliminate them.
- Presence is in memory on a single instance: it resets on restart, needs one machine (`fly deploy --ha=false`), and lags up to ~10 s.
- No login rate limiting and no CSRF token (cookie is SameSite=Lax).
- Edits typed in the last second before navigating away can be lost.
- `npm audit`: 3 moderate findings (sprintf-js via argparse, mammoth CLI only), not reachable from the server.
